# 智能体笔记：从手机操作智能体

Status: implemented

[English](2026-11-07-mobile-agent-surfaces.md) | 中文

## 问题

[手机布局](2026-11-06-phone-layout-shell.zh.md) 给外壳只留了一个界面——会话——而真正用来操作智能体的那些界面被留在了后面。工具调用的详情无法到达：框架在手机上拒绝 `openDetails()`，而该列解析为零宽。审批与提问接管卡带着指针形状的几何尺寸到来：右对齐的 36px 操作按钮、336px 的主体上限，且与活动视口没有任何关系，因此键盘打开的 phone 会把答复挤出屏幕。

## 决定

**详情是同一个面板，作为第二个界面渲染。** `ui-layout` 不再在手机上拒绝详情请求；宽度偏好继续决定面板是否显示，`AppFrame` 把该标志变成覆盖会话的整屏表面，而不是一条轨道。`DetailsPanel` 不需要第二份实现，也不需要新状态：关闭仍来自它自己的按钮，而既有的「切换会话时关闭详情」规则同样会关闭该表面。`openDetails`/`closeDetails` 仍是工具卡片已经在调用的唯一入口。

**该表面用 visibility 而非 transform 隐藏。** 被变换的祖先会成为 `position: fixed` 后代的包含块，因此给该表面加动画会使其内部任何固定定位元素错位。同一个陷阱已经影响到 `ui-settings`——它的面板是侧边栏列的固定定位后代，而 Phase 9 用 `translateX` 给那一列加了动画；那是下一阶段的问题，本决定让详情表面避开它。

**接管卡针对视口重排。** 审批卡把两个答复在全宽内纵向堆叠、主操作在下方，并把理由主体限制为 `min(50dvh, …)`；提问与计划审查卡限制为 `min(60dvh, 520px)`（带 `vh` 回退），并让底部在放不下时换行而不是溢出。触控目标沿用组件原语已有的尺寸——36px 按钮、40px 提问选项——该表面自身的关闭控件在手机上放大到 36px。

## 考虑过的替代方案

**在 overlay 槽中注册一个独立的手机表面组件。** 被否决，因为详情面板本身已经是其槽内容的拥有者：第二个组件要么重复该面板，要么需要把该槽渲染到框架之外，而槽系统不允许——插件只能渲染自己声明的槽。

**像抽屉那样用 `translateX` 给表面加动画。** 因上述包含块陷阱被否决。以 visibility 与 opacity 换掉滑动效果，换来面板内每个固定元素都相对视口定位。

**用手势关闭该表面。** 本阶段被否决：面板的关闭按钮已经存在，且是桌面端使用的同一入口，而滑动手势需要指针跟踪，现阶段没有其他界面提出该需求。

**让详情面板在手机上继续不可达。** 被否决，因为正是它迫使用户回到桌面去读工具调用的参数，而这一循环正是本阶段要闭合的。

## 后果

从手机出发，用户可以读取工具调用详情、答复审批、回答提问，而无需离开设备。断点以上没有任何变化：详情列保留其拖动手柄与让步行为，接管卡保留右对齐的单行操作。

代价是明确的。该表面共享桌面的宽度偏好，因此手机可能打开一个桌面设定过宽度的面板——无害，因为该表面忽略宽度，但这意味着手机没有独立的「打开」状态。在包含块陷阱被修复之前，设置页在手机上仍不可达，因为那个面板是被动画祖先的固定定位后代。这些界面的设备验证仍是手工步骤：智能体环境无法启动浏览器，因此已提交的 e2e 场景在 CI 中运行。
